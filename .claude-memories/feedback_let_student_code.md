---
name: Let the student write the code
description: Don't write full implementations — give hints, structure, and let the student code it themselves
type: feedback
---

Don't write full code implementations for the student. When the mentor did too much infrastructure setup (migrations, entity fixes, circular ref resolution) without letting the student participate, they got frustrated and said "I should have done myself so I learn."

**Why:** The student learns by doing, not by watching. Writing code themselves builds muscle memory and real understanding. When the mentor does it, the student misses the learning opportunity.

**How to apply:** Give the skeleton/structure, explain what each part should do, provide small hints when stuck — but let the student write the actual code. Only write code for them when they explicitly say "do it for me" or "fix this for me." For tooling/config issues (not learning objectives), it's OK to fix directly.
